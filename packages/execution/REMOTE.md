# Remote hosted execution integration — implementation contract

The trusted control plane owns admission, D1, the vault, run/attempt generations, public R2 logs/outputs, and retained caches. The execution account receives only an immutable `RemoteAttemptGrant` and an attempt-scoped callback capability. It has **no** trusted DB, ADMISSION, ATTEMPTS, SECRETS, GIT_SERVICE, API service binding, tenant ACL mirror, or general internal service key.

Shared types/crypto: `packages/execution/src/remote/protocol.ts` (execution-control owner). Remote Worker owner: `workers/hosted/**` and `tests/high-level/execution-remote-host.test.ts`. Do not edit another owner's files. Coordinate additions here.

## Remote Worker exports/bindings

- `workers/hosted/src/index.ts`: default private HTTP handler, `HostedAttemptWorkflow`, `RemoteAttemptController`, `HostedSandbox`, and pinned SDK `ContainerProxy`.
- `HOSTED_WORKFLOW: Workflow`, `HOSTED_ATTEMPTS: DurableObjectNamespace<RemoteAttemptController>`, `SANDBOX: DurableObjectNamespace<HostedSandbox>`, `BACKUP_BUCKET: R2Bucket` (ephemeral, execution-account only), `HOSTED_EXECUTOR_ID: string`, `HOSTED_CONTROL_KEY: string`, `HOSTED_CALLBACK_ORIGIN: string`, `HOSTED_PROFILES_JSON: string`, `ENVIRONMENT`.
- Optional explicit test-only transport/loopback selection may be supplied; production HTTPS is mandatory. No fake VM result when Container/SDK bindings are missing.
- SDK calls must execute from `HostedAttemptWorkflow`. Reuse `@cloudflare/ci@0.2.0` and `@cloudflare/sandbox@0.12.1`.
- Control commands: signed POST `/internal/hosted/attempts/:id/accept` body `RemoteAttemptGrant`; `/status` and `/cancel` body `{generation,grant_digest,challenge,reason?}`. Accept durably journals before ACK and starts/reconciles exactly one deterministic Workflow/runtime. Status/cancel return `SignedRemoteStatus`, challenge-bound with `HOSTED_CONTROL_KEY`. Accept may return a signed status with challenge equal to the grant digest.
- Remote alarms + a scheduled reaper seal expired runtimes, terminate process groups, destroy via SDK, verify `ctx.container.running === false`, wait for outstanding SDK operations, delete every tracked ephemeral R2 object and verify absence. An uncertain cleanup is never a destroyed receipt. Sealed IDs cannot restart. Persist normalized completion drafts before a Workflow checkpoint; replay never reruns uncertain commands.

## Shared real-CI entry point (provided by control owner)

`runSdkJob(ctx, namespace, adapter, event, step)` in `packages/execution/src/hosted/sdk.ts` invokes the actual CI SDK pipeline through a narrow namespace adapter. `SdkJobAdapter` has `sdk_contract: 'gitknot-sdk-adapter-v1'`, `context: {attempt:{id,repo_id,account_id,runtime_name},run:{commit_sha,source_ref}}`, `sandbox` (real SDK handle), `source:{url,commit,token}`, and methods `remaining(reserve?)`, `checkout()`, `executeCommands():Promise<number>`, `snapshot():Promise<DirectoryBackup>`, `destroy()`, `safeLogSummary()`. `prepareSource():Promise<void>` is called inside the SDK step's source provider, before checkout, so no source/secret value becomes a Workflow checkpoint. The adapter must durably claim the execution once there; unknown replay attaches/reaps rather than executing again. `runSdkJob` returns no user success assertion; final receipts remain independently fenced.

Existing root-only helper scripts are exported from `packages/execution/src/hosted/scripts.ts` and `output-script.ts`. They provide exact source/cache/file archive boundaries. `HostedLogs` currently writes through trusted bindings, so the remote adapter supplies its own callback sink. The remote sandbox must run job processes as uid/gid 10000 with no-new-privileges, fixed process groups, hard deadlines, quotas, closed default networking, HTTPS interception and exact-host quotas. No callback/platform credential is injected into the job.

## Attempt-scoped callbacks (control owner implements)

Callback base: `${grant.callback.origin}/internal/hosted/attempts/${grant.attempt_id}/:action`. Authenticate with `signCallbackRequest` using `grant.callback.token`; all JSON bodies include `{generation,plan_digest,...}`. The token is private to the remote Worker/DO and never belongs in a job workspace or Workflow step return. The control plane rechecks current attempt, generation, producer, lease/deadline, repository/actor policy and declared resources on every call. Unknown actions/objects, arbitrary SQL, ACL assertions, and other attempts are rejected.

- `begin` → `RemoteBeginResult` with transient GitKnot `source`, declared inputs and lease; `execute:false` is attachment/closed state, never permission to rerun commands.
- `heartbeat` `{egress_bytes,egress_requests}` → `{status,lease_expires_at}`; only returned leases extend authority.
- `checkout-complete` `{}` revokes the transient checkout capability.
- `process` `{process_id}` journals the concrete SDK process ID.
- `secrets` `{step_id,names}` → `{values,expires_at}` for exact declared versions, immediately before the step. Keep values in memory; redact before logs/checkpoints; sanitize outputs/snapshots.
- `input` GET `?generation=&plan_digest=&object_id=` streams one listed `RemoteInput`, never an arbitrary key.
- `log` `{sequence,data_base64,sha256,size_bytes}` → `RemoteStoredObject`; one attempt-wide contiguous sequence, ≤256 KiB chunks, already statefully redacted. Control plane also masks known values.
- `output` `{name,sequence,final,data_base64,sha256,size_bytes,content_type}` → `RemoteStoredObject`; declared names/type/retention and streamed aggregate quotas are authoritative in the frozen job.
- `log-manifest` `{}` → `RemoteStoredObject`; `output-manifest` `{name,sha256}` → `RemoteStoredObject`. CP verifies complete contiguous chunks and the complete output checksum.
- `checkpoint` `{receipt: RemoteCompletion}` durably records a sanitized completion draft without accepting a check; `process_group_stopped` in the draft reflects actual process termination, not a guessed success.
- `complete` `{receipt: RemoteCompletion}` accepts only current identity and after independent, authenticated `/status` confirms sealed destruction, no in-flight operations and no ephemeral objects. Report actual command failures, signals/unknown signal, quota exhaustion and infrastructure failures separately.
- `destroyed` `{}` asks CP to independently query the configured remote executor; caller-provided destruction booleans are not evidence. Cleanup remains callable after lease expiry; results do not.
- `cache-get` `{cache_key}` → `RemoteCache|null`; `cache-read` GET uses the same query identity plus `object_id`. Namespace is CP-derived from repo, trust, producer, toolchain and declared cache. A hit restores only dependency paths; verification always executes.
- `snapshot-upload` POST **binary** body, signed with `x-gitknot-content-sha256`, headers `x-gitknot-generation`, `x-gitknot-plan-digest`, `x-gitknot-snapshot-id`, `x-gitknot-snapshot-part: archive|metadata`, and `content-length`; result `RemoteStoredObject`. Stream with checksums/quotas. This copies an SDK-sanitized ephemeral R2 backup to retained CP R2; remote credentials are never presigned R2/provider credentials.
- `snapshot-commit` JSON `RemoteSnapshotCommit` → `RemoteCache`. Secret-bearing/read-only-cache jobs may only produce metadata-only snapshots and never publish a writable cache. Retention and real deletion occur in CP R2. Restore copies the two permitted files into ephemeral R2 for SDK `restoreBackup({id,dir,localBucket:true})`. Delete the ephemeral originals/imports before confirming teardown.

Lifecycle response/complete facts include the exact `executor_id`, producer from the grant, logical `runtime_id`, actual SDK `sandbox_id`, generation, immutable grant digest, deadline and a fresh challenge. Cross-account tests exercise isolated environments and HTTP; physical Container/network acceptance is separate and remains unrun.
