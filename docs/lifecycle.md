# Durable repository lifecycle

`OperationWorkflow` is the durable orchestrator for provision, import, fork, export/backup, restore, rename, accepted transfer, archive/unarchive, deletion/purge, and shard movement. The core `operations` record is the public authority; remote completion is only accepted after actual native Git/storage verification. Individual steps have stable idempotency keys and persisted receipts. A timeout leaves an uncertain operation recoverable and fenced rather than reporting success.

Native storage follows `docs/git.md`: scope `git-service`, `POST /internal/git/repositories/:repo_id/provision`, `/mutate`, `/export`, `/reconcile`, `GET /operations/:operation_id`, and token-bound `/barrier` POST/DELETE. Mutation requests are `{operation_id,actor,mutation}`. Only `PublicationResult.outcome === 'committed'` with read-back evidence is completion.

Additional native contracts needed by lifecycle/scan workers (all under the same authenticated prefix):

- `POST /internal/git/repositories/:repo_id/verify`: `{operation_id,expected_refs?}` → `{verified:true,refs:[{ref,oid}],objects_verified:true}` after native fsck and ref inventory.
- `POST /internal/git/repositories/:repo_id/restore`: accepts a complete native bundle stream, content SHA-256, operation ID, target fresh storage name, and expected refs; verifies the bundle and exact accepted refs before returning the verification receipt. It must enter the same fenced publication path.
- `POST /internal/git/repositories/:repo_id/purge`: `{operation_id,storage_name,retained_refs:[]}` → `{deleted:true,verified:true}` only after actual backend deletion is confirmed. Refuse referenced fork/review objects until preserved independently.
- `POST /internal/git/repositories/:repo_id/scan`: `{commit_oid,cursor,limit}` → a bounded tree/blob page pinned to that commit, including exact path, OID, size, UTF-8 text or explicit binary exclusion; return `next_cursor` and `complete`. No arbitrary checkout, branch drift or repository code execution.

Private source credentials are broker references, never source URLs with embedded credentials or workflow checkpoint values. The secrets broker's narrow `operations.import` call takes only an existing operation ID, rechecks its actor/source-secret grant, and returns a transient source Authorization value used in the same call frame as native import.

Portable archives include a versioned manifest, complete native Git bundle/ref inventory, canonical collaboration rows and Markdown, referenced bytes, checksums and lineage. `archive_snapshots` and `archive_snapshot_rows` capture all metadata in one D1 transaction; paged R2 serialization reads that immutable materialization. Metadata parts use the `snapshot-v2` generation, so an older interrupted live-page export cannot mix into the materialized archive. Foreign-key closure is checked before verification, including non-runnable operation summaries needed by workspaces, suggestions and merge queues. Secret inputs, executable operation checkpoints and runtime credentials are excluded.

Repository-readable archives contain only explicitly classified repository-shared document histories. Private drafts, draft revisions, and draft-related history/IDs are excluded before materialization and R2 serialization, including in automatic backups. Their user ownership does not become repository ownership when the same history table stores both kinds. Cached snapshots containing unclassified/private draft history require a fresh capture. Owner-scoped account exports separately preserve the initiating user's current drafts, immutable revisions and draft audit metadata under their captured user/context authority. A shared repository restore preserves live private drafts and their history, detaching an item link only when that item is absent from the restored snapshot.

`portableArchiveStream(env, manifest, authorizePart)` requires an async current-authorization callback. Public callers use `archiveAuthorizer(c, archiveId)`, which opens fresh primary-backed contexts and checks every persisted historical source audience. The stream rechecks after storage reads before releasing bytes. Candidate and review-snapshot refs have persisted source/oid mappings, and the actual Git bundle header must match the verified ref inventory. The downloadable TAR's checksum is separate from its internal manifest checksum.

`repository_metadata_fences` is a placement-local write fence, independent of repository state/revision and the native barrier. Its receipt is `{repo_id,operation_id,routing_epoch,fence_id}`. Every repository metadata CAS checks either absence of a held fence or the exact owner receipt through core's `inRepositoryMetadataFence` / `repositoryMetadataFenceGuard`. Acquisition IDs are immutable and released acquisitions cannot be reacquired. Release commits the lifecycle release checkpoint before tombstoning the fence, so recovery never needs a stale held-owner tail.

Automatic backups capture the repository itself, fork source, pull-request heads, historical patch heads, candidate sources, historical review sources, and task workspaces using seven bounded reads in one D1 batch. This avoids workerd's compound-SELECT limit while preserving every historical audience. Audience and ref-audience writes use the same exact metadata-fence receipt as snapshot materialization. Git bundles and referenced bytes finish their immutable capture before the public fence is released.

A definitive read-only capture failure records `snapshot_abandoning` before requesting native release. Native independently checks for an uncertain canonical publisher. The final D1 batch expires the incomplete archive, retains its private upload/deletion evidence and financial holds, marks `snapshot_abandoned`, and tombstones the exact metadata receipt. Directory release is repeatable after that batch, including a lost acknowledgement. The abandoned acquisition cannot resume as an ordinary writer; a new capture uses a new operation. Completed captures retain their normal resumable release checkpoint. `events-workerd.test.ts` verifies successful and failed captures followed by ordinary API metadata writes, vault writes, and valid compiler previews.

An empty restore request undeletes retained current Git/R2/metadata. It does not select an older backup. Explicit `archive_id` restores stage a fresh, immutable metadata plan and new standalone-billed object IDs/keys, verify the fresh native Git target, and atomically apply the matching metadata with deferred foreign-key validation. Referenced historical operations are non-runnable; active queues/claims/workflows are retired. Metadata/byte verification and previous-object physical/financial cleanup complete before activation. The current owner and account authority govern the restore. A private fork audience may traverse the restoring base's own deleted lifecycle only under its exact held restore fence; real source grant, credential and policy denials remain effective.

Transfers recheck both receiving `repositories.create` and `repositories.transfer`, the original credential ceilings and current account policy at the owner CAS. Billing follows prepare → owner CAS/`storage_effective_at` → financial commit → verified per-object metadata receipt application → activation. Both account authority barriers cover publication.

Movement first verifies execution quiescence, drains existing deletions/deliveries, and captures an immutable final `move_source_rows` snapshot. It validates normal consumer, catalog, object and archive receipt parents against the same union it selected. Destination placement enrollment and source global-ID backfill precede cutover. Fresh shards receive only minimal disabled foreign-key material, never copied user credentials or grants. Runner control state stays identity-owned; pool/enrollment/runner rows move only when immutable locators declare repository authority, together with repository-scoped exchange/retirement projections, local hosted checkpoints/log chunks and workflow previews.

Scheduled backup/purge and credentialless moves use registered `operations_maintenance_intents`, created with the operation. Native maintenance export checks that purpose and its live barrier. Staged credentialless restore consumes the signed live-source `move-restore-authority` contract from `docs/git.md`; copied intent rows cannot authorize it.

Private move submission consumes a positive `expected_epoch` with a stable supplied or deterministic `operation_id`. The locator commits before creation acknowledgement. Repeating an uncertain submission recovers the same operation, including after cutover. Finalization and barrier-release receipts are resumable without reacquiring a released native barrier.

## Physical storage placement handoff

Movement uses the billing-owned placement protocol implemented by `@gitknot/billing` and migrations **077/102**. The account identity stays fixed. The source/destination cells, metadata shards, source/target epochs, provider storage names, financial slices and operation fence are durable; cleanup reads the recorded physical source after directory cutover.

```ts
prepareRepositoryStoragePlacement(env, {
  operation_id, repo_id, source_cell_id, source_shard_id,
  target_cell_id, target_shard_id, source_epoch,
}): Promise<PlacementProgress>;
copyRepositoryStoragePlacement(env, { operation_id }): Promise<PlacementProgress>;
commitRepositoryStoragePlacement(env, { operation_id, effective_at? }): Promise<PlacementProgress>;
finalizeRepositoryStoragePlacement(env, { operation_id }): Promise<PlacementProgress>;
abortRepositoryStoragePlacement(env, { operation_id }): Promise<PlacementProgress>;
// PlacementProgress = {operation_id,state,processed,remaining,fence}
```

Ops' `repository_move_controls` journal freezes inventory and the effective timestamp. It repeats each bounded billing phase until `remaining` is false. Preparation validates the live immutable move request and source metadata fence, then reserves temporary duplicate byte/object caps and account/platform commitments. The destination's R2, backup and execution-snapshot objects each have one durable writer generation. Conditional writes and positive size/SHA-256/ETag receipts reconcile lost acknowledgments. An absent object after an uncertain write retains its grant and both lifecycle fences; timeout never proves a cancelled upload.

Canonical Git and the temporary restore bundle have separately reserved exposure before provisioning/staging. Native publication consumes the canonical reservation through the existing Git billing gate. The temporary bundle is checksummed, generation-fenced, and physically deleted before its hold settles. Full native graph/ref verification gates the target; a mismatched ref inventory cannot activate it. Private `/internal/git/storage-placement` operations address the exact recorded provider namespace and cell, including source cleanup after the directory changes.

Financial commit atomically switches each existing logical object's physical selector without changing its payer, public object ID or upload reservation/fence. `StorageObject.storage_cell_id`, `storage_epoch`, and the target platform-object selector identify the verified destination. Source and destination physical costs remain metered during overlap; customer logical byte-time switches at the one immutable `effective_at` boundary. The source copy remains held until actual deletion is verified. Ops applies receipt-backed manifest/LFS fields in its own guarded transactions, verifies all metadata, changes the directory while the destination remains fenced, finishes source cleanup, and only then activates/releases the move.

Ordinary same-cell shard moves publish the new metadata epoch while retaining the existing physical buckets and allocation; their target slice IDs are null. Explicit archive recovery has an immutable `archive_restore` purpose and funds a fresh canonical namespace and exact archive scratch bytes even within the same cell. It verifies the historical archive refs rather than the newer live graph. Cross-cell account admission stays at the recorded identity-authoritative coordinator home, and capacity requests reach the slice's actual cell. New post-cutover uploads use the destination cell's configured slice. No account billing authority is replicated into repository metadata.

Rollback first closes all participating billing controllers, then reconciles the original native journal and operation-bound namespace creation evidence before any R2/scratch/canonical deletion. The backend contract is `reconcilePublisher(placement, side): Promise<PlacementPublicationFence>` plus `observeCreation(placement): Promise<PlacementGitCreationProof|null>`. A strict positive terminal/closed/finalized native receipt survives removal of staged metadata. The full-digest namespace name preserves both repository and operation identities; an unpredictable create-time marker and immutable provider ID establish target ownership. A missing marker, lost rejection or mere existence/404 cannot resolve an uncertain create or publisher. Unknown work retains its original holds and fences, and native financial settlement records only the actual publication outcome.

Ops releases/checks the source native barrier while destination proof metadata is still present, then discards owned staged metadata, advances the source metadata epoch and tombstones the released fences. A post-commit move finishes forward. Immutable phase receipts make lost commit, deletion and release acknowledgments safe to replay. Transactional closed-generation checks reject delayed acquisitions even when they already read a pre-abort placement.

### Placement recovery checkpoints

Migration **096** adds identity-primary `repository_move_controls` and placement-local inventory/receipt tables. The control pins both metadata-fence IDs, source and destination epochs/store names, archive and metadata digests, and the complete physical inventory digest/count. `move_physical_objects` includes general manifests, execution objects, SDK snapshot archive/metadata keys, and stored financial objects whose feature-link receipt is incomplete. Object identity, SHA-256, original ETag, custom metadata, and HTTP metadata remain immutable.

The closed `verified → cutover` decision fixes `effective_at` once, before Billing switches financial selectors. `move_applied_storage_receipts` records the permitted manifest/LFS field changes without changing `move_source_rows` or its digest. Directory routing then advances while the destination repository remains moving and metadata-fenced. Billing verifies source physical deletion and settles the duplicate holds; only then does Ops activate the destination and release both acquisitions. `source_retained_until` describes retained source metadata/recovery history; physical source copies have a separate verified deletion receipt.

Signed `operations.maintenance` calls to `/internal/operations/move-recover` and `/internal/operations/move-abort` take `{operation_id}`. The coordinator always returns to the immutable source recorded in the identity journal, including after directory cutover. Cron dispatch also follows that control until terminal, even if a public operation completion acknowledgement was lost. A pre-cutover rollback reopens the source at `target_epoch + 1`, preserving both original participant epochs as tombstones. A committed cutover must finish forward.

`events-movement.test.ts` exercises lost R2/native/account/directory replies, exact customer versus overlapping platform byte-millisecond quantities, verified rollback, and a late original writer. `events-move-workerd.test.ts` runs the full two-cell path with distinct real D1/R2 bindings, production admission Durable Objects, native Git processes and the signed Git gateway. Its R2 writer carries an exact `FixedLengthStream` through the checksum transform.

Verification coverage includes real native Git across two cells, historical archive recovery into a same-cell shard, R2/SDK snapshot copies, lost provider/native/financial acknowledgments, unknown-write rollback, delayed acquisitions, ref mismatch, source cleanup failure, metadata-only moves and post-cutover uploads/deletes. The final creation-proof/native/Git/movement gate passed **39/39 tests across four files**, including preservation of a real foreign Git namespace after a lost create-only rejection and recovery from a fsynced creation receipt after a lost successful reply. Billing's dedicated delayed-acquisition and same-cell archive-recovery regressions also passed; the separate workerd account-export failure and parent-gate status are recorded in `docs/billing.md`. No deployment or remote migration was run.
